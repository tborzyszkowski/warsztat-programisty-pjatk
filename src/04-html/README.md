# 04. HTML, CSS i JavaScript: portfolio w sieci

## Cel działu

Celem działu jest utworzenie od podstaw niewielkiej, semantycznej strony portfolio,
a następnie opublikowanie jej jako statycznej witryny przez GitHub Pages. Student pracuje
bez frameworków, obserwuje efekt w przeglądarce po każdym etapie i potrafi wyjaśnić rolę
trzech podstawowych technologii WWW.

Po wykonaniu działu student potrafi:

- utworzyć dokument HTML i opisać treść za pomocą elementów semantycznych,
- połączyć wiele stron wspólną nawigacją i używać ścieżek względnych,
- dołączyć zewnętrzny arkusz CSS i dopasować układ do wąskiego ekranu,
- wybrać element DOM i zareagować na zdarzenie kliknięcia w JavaScript,
- użyć DevTools do sprawdzenia drzewa strony, stylów i błędów skryptu,
- opublikować pliki z gałęzi `main` przez GitHub Pages i sprawdzić publiczny adres.

## Wymagania

- edytor tekstu lub IDE, np. Visual Studio Code albo WebStorm,
- aktualna przeglądarka: Chrome, Edge lub Firefox,
- podstawowa znajomość pracy z plikami i katalogami,
- konto GitHub oraz repozytorium do publikacji w ostatnim temacie.

Nie instalujemy frameworków ani generatorów projektu. Wystarczą zwykłe pliki HTML, CSS
i JavaScript. Podgląd można uruchomić przez otwarcie `index.html` w przeglądarce; serwer
deweloperski jest opcjonalny.

## Zalecany sposób pracy

1. Utwórz mały fragment i zapisz plik.
2. Zanim odświeżysz stronę, przewidź, co powinno się zmienić.
3. Sprawdź rezultat w przeglądarce i porównaj go z przewidywaniem.
4. Jeśli coś nie działa, zmień jedną rzecz naraz i sprawdź komunikaty w DevTools.
5. Po działającym kroku wykonaj mały eksperyment, po czym wróć do wersji bazowej.

## Wspólna checklista

- [ ] Każda strona ma poprawny szkielet HTML i opisowy tytuł karty.
- [ ] Treść ma logiczną hierarchię nagłówków i używa elementów zgodnie z ich znaczeniem.
- [ ] Linki i zasoby działają przy otwarciu strony z innego katalogu niż edytor.
- [ ] Arkusz CSS jest dołączony zewnętrznym elementem `link`.
- [ ] Strona mieści się na wąskim ekranie, a interaktywne elementy są czytelne.
- [ ] Konsola przeglądarki nie pokazuje błędów JavaScript.
- [ ] W repozytorium i opublikowanej witrynie nie ma haseł, tokenów ani prywatnych danych.
